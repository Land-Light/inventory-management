# 棚卸アプリ

JANコード、商品名、予定数を登録し、棚卸し数量を入力して差異を確認するWebアプリです。部屋コードまたは共有リンクで、複数端末から同じ棚卸しデータを扱えます。

## Netlifyなしで使う

このアプリはビルド不要の静的サイトです。Netlifyを使わず、次のどちらかで使えます。

### 同じPCで使う

PowerShellでこのフォルダを開き、次を実行します。

```powershell
.\start-local.ps1
```

表示された `http://127.0.0.1:4175` をブラウザで開きます。同じPC上の `localhost` / `127.0.0.1` は安全な環境として扱われるため、カメラ読取も使えます。

### 複数端末で使う

複数端末でカメラ読取を使う場合は、HTTPSで開ける静的ホスティングにこのフォルダの中身をアップロードしてください。GitHub Pages、Cloudflare Pages、Vercel、Firebase Hostingなどで動きます。

アップロードするファイルは主に次です。

- `index.html`
- `styles.css`
- `app.js`
- `zxing.min.js`
- `supabase-config.js`
- `.nojekyll`

### GitHub Pagesに置く場合

1. GitHubでリポジトリを作ります。
2. `github-pages-upload` フォルダの中身をリポジトリ直下へアップロードします。
3. リポジトリの `Settings` > `Pages` を開きます。
4. `Source` を `Deploy from a branch` にします。
5. `Branch` を `main`、フォルダを `/ root` にして保存します。
6. 数分後に表示される `https://ユーザー名.github.io/リポジトリ名/` を開きます。

GitHub PagesはHTTPSなので、スマホから開いてもカメラ読取を使えます。

## 端末間同期の設定

共有データはSupabaseを保存先として使います。

1. Supabaseで新しいProjectを作成します。
2. SQL Editorで `supabase-schema.sql` の内容を実行します。

すでに以前の版で `inventory_rooms` だけ作っている場合は、もう一度 `supabase-schema.sql` を実行してください。商品用の `inventory_products` と入力明細用の `inventory_count_entries` が追加されます。

部屋の期限切れ削除だけを追加する場合は、既存テーブルに `created_at` 列と削除ポリシーを追加するため `supabase-add-room-expiry-columns.sql` だけを実行してください。

3. Supabaseの Project Settings > API から、Project URL と anon public key を確認します。
4. `supabase-config.js` に貼ります。

```js
window.INVENTORY_SUPABASE = {
  url: "https://xxxxxxxx.supabase.co",
  anonKey: "xxxxxxxx"
};
```

5. ローカル利用ならブラウザを再読み込みします。静的ホスティングに置いている場合は、更新した `supabase-config.js` を再アップロードします。

## 使い方

- 最初の端末で担当者名を入力し、「部屋を作る」を押します。
- 表示された部屋コードを伝えるか、「リンクコピー」で共有リンクを送ります。
- 別端末はリンクを開くか、部屋コードを入力し、担当者名を入れて参加します。
- データは約3秒ごとに同期されます。
- 入力画面には、その端末で入力した明細だけが表示されます。
- 未登録商品を入力する場合、数字だけならJANとして、文字を含む場合は商品名として仮登録します。
- 棚番は数字だけなら3桁にゼロ埋めし、英字や記号を含む棚番も20文字まで入力できます。
- 確認画面では全端末の入力が合計され、商品ごとに棚番と担当者別の内訳が表示されます。
- 確認画面ではJAN / 商品名 / 担当者検索と「差異ありだけ表示」で確認表を絞り込めます。差異確認は差異の絶対値が大きい順に並びます。
- 部屋に入った直後は設定画面がロックされています。商品マスタを変更するときだけ「ロック解除」を押し、確認欄に `解除` と入力してください。変更後は「ロックする」で再ロックできます。
- 部屋は作成から7日経過すると削除されます。アプリ起動・入室時に期限切れのローカル部屋とクラウド部屋を掃除します。

## データ構造

同時入力に強くするため、部屋全体を丸ごと上書きせず、テーブルを分けています。

- `inventory_rooms`: 部屋
- `inventory_products`: 商品マスタ
- `inventory_count_entries`: 入力明細

入力明細は1回の入力ごとに1行で保存されるため、複数人が同時に入力しても上書き衝突が起きにくい構造です。

## CSV取込

CSVの列名は次に対応しています。

- `jan` または `barcode`, `code`, `sku`, `商品コード`, `JANコード`, `バーコード`, `品番`, `品目コード`, `管理コード`
- `name` または `product`, `item`, `description`, `商品名`, `商品名称`, `品名`, `品目名`, `品目`, `名称`, `商品`, `明細名`
- `expected` または `stock`, `qty`, `quantity`, `予定数`, `理論在庫`, `在庫数`, `個数`, `数量`, `数`, `在庫`, `現在庫`, `総数`

関係ない列が混ざっていても無視します。既存商品はCSVにある列だけ更新でき、予定数列が無い場合は既存の予定数を残します。在庫数は `100点` や `1,000` のような表記も数値として読み取り、金額・価格・原価・販売価格などの列は予定数として扱いません。JANだけの行は商品名にJANを仮設定し、商品名だけの行は `NOJAN-...` の仮コードで取り込みます。

JAN未入力で商品名だけ仮登録したあと、同じ商品名にJANが入ったデータを取り込むと同一商品として統合します。JANだけで仮登録した商品も、あとから同じJANの商品名が入ると商品名を更新します。列名が合わない場合やヘッダーが無い場合も、8桁・12桁・13桁・14桁などの商品コードらしい数字列を判断材料にして取り込みます。`商品ID / 商品コード / 商品名` のように1つのセル内へコードと商品名がまとまっているCSVも、商品コードらしい数字と商品名を分けて読み取ります。

## CSV出力

CSV出力は確認画面の差異表とは別の出力用表を使います。列は左から `商品コード`, `棚卸数量`, `明細メモ` です。商品コードにはJAN、棚卸数量にはJANごとの入力合計、明細メモには担当名を含めない棚番別の数量内訳を出力します。出力用表とCSVは商品コードの小さい順に並びます。


## カメラ読取

Chromeなど `BarcodeDetector` 対応ブラウザでは標準機能を使います。Safariなど未対応ブラウザでは、ZXingをCDNから読み込んで読取を試します。カメラ利用にはHTTPSが必要です。ただし、同じPCで `localhost` または `127.0.0.1` から開く場合はカメラを使えます。
